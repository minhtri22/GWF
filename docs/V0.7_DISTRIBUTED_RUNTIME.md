# v0.7 Distributed Runtime

v0.7 introduces the first durable multi-worker execution layer.

The scheduler is deliberately small and database-backed. It does not add Redis, Kafka or Celery as an authoritative state source. PostgreSQL remains the durable coordination plane, while SQLite remains the local/test backend.

Key guarantees:

- durable jobs survive process restart;
- lease token plus expiry defines execution ownership;
- heartbeat extends leases;
- crashed workers are recovered by lease reaping;
- abandoned execution runs are recorded rather than silently overwritten;
- retry delivery is at-least-once;
- authoritative effect commit is exactly-once by effect_key;
- job resource requirements are matched to worker capacity and capabilities;
- existing resource conflict keys are reserved across workers;
- scheduler transitions are written to scheduler_events and audit.

v0.7 does not yet implement a network worker protocol or Kubernetes autoscaling. Those are platform concerns that can sit on top of this durable contract.
