# v0.5.1r1 PostgreSQL Gate Hardening

This revision does **not** claim the live PostgreSQL gate has passed. It hardens the candidate before that gate is executed.

Changes:

1. The append-only audit test is backend-neutral. It asserts the database guard and its `append-only` reason instead of requiring SQLite's exception class.
2. `preflight_v051_postgres.py` verifies a real PostgreSQL connection, server version, schema creation/drop, commit, and rollback before the 41-test matrix starts.
3. The gate runner executes that preflight first and fails closed.
4. A GitHub Actions workflow is included. It starts a real `postgres:17` service container, installs `psycopg`, runs the preflight, the same SQLite/PostgreSQL test matrix, six research cases, restart persistence probe, semantic equivalence comparison, and only then asserts `v06_unblocked=true`.
5. No database credential is written to evidence; DSNs are redacted by the preflight tool.

The acceptance criterion remains unchanged: **v0.6 must not start until live PostgreSQL evidence says PASS**.
