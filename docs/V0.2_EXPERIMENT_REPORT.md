# GWR v0.2 — Research Orchestrator Experiment Report

## Objective

Test whether the v0.2 runtime can execute the 17-phase research domain end-to-end with durable checkpoints and distinct handling for:

- research outcome `PASS`,
- research outcome `FAIL`,
- research outcome `PIVOT`,
- retryable runtime failure,
- upstream semantic recovery,
- explicit pause/resume.

The executor used for these acceptance experiments is deterministic and synthetic. Therefore the experiment validates **workflow/runtime semantics**, not any external scientific hypothesis.

## Scenario observations

### PASS

The workflow executed phases 00–12, skipped phase 13 because the decision was PASS, then completed replication/replay, final report, and handoff. All current artifacts ended `VALID`; no runtime failures remained.

### Scientific FAIL

The phase-12 `decision_record.outcome=FAIL` did **not** create an operational `FailureRecord`. The workflow still executed replication/replay, final report, and handoff and terminated normally with research outcome FAIL. This confirms the required distinction between falsified/unsupported hypothesis and runtime malfunction.

### PIVOT

Generation 0 reached phase 12 with PIVOT, executed phase 13, created an approved pivot plan, checkpointed, marked the current `protocol` lineage root dirty, invalidated only affected descendants, and resumed from phase 04. Generation 1 regenerated the affected downstream path, reached a new PASS decision, then completed replication/report/handoff. The runtime recorded a `REPLAN -> protocol` decision. The old pivot plan became stale after its upstream decision revision was superseded, which is expected provenance behavior.

### Retryable runtime failure

The first main-experiment attempt injected `runtime_timeout`. The runtime created one `FailureRecord`, checkpointed the failure, chose `RETRY`, reused the same WorkUnit, incremented the ExecutionRun attempt number, then succeeded. The failure was resolved only after the phase passed its completion gate. No open failure remained.

### Upstream semantic recovery

The pilot injected `protocol_mismatch`. Detection occurred at execution, while the confirmed root was the protocol revision. The runtime:

1. recorded the failure,
2. confirmed the root through a human-authorized action,
3. marked the root dirty,
4. computed the affected subgraph,
5. created and applied a RecoveryPlan,
6. checkpointed,
7. resumed from `phase_04_design_protocol`,
8. regenerated only the downstream path,
9. resolved the original failure after the repaired root phase passed.

The run then completed normally.

### Pause/resume

A run was deliberately stopped after three orchestration steps using a max-step guard. The checkpoint persisted next phase, generation, history, current hashes and kernel snapshot. A new `resume()` call reconciled current database truth and completed the remaining phases under the same orchestration ID.

## Additional governance experiment

An automated test starts the workflow without an approval provider. The first normative output creates a frozen proposal and pauses with `WAITING_APPROVAL`. After an external HUMAN actor approves the exact proposal hash, the orchestration resumes from checkpoint and completes. The temporary `approval_missing` operational failure is resolved on approved resume.

## What v0.2 therefore demonstrates

The implementation now demonstrates an executable control loop:

```text
phase -> run -> artifact/evidence -> completion gate
  -> PASS -> checkpoint -> next phase
  -> operational failure -> retry/recovery -> checkpoint -> resume
  -> research PASS/FAIL -> replication -> report -> handoff
  -> research PIVOT -> approved pivot -> invalidation -> new generation -> resume subgraph
```

It also demonstrates persistent provenance, revision immutability, human-controlled normative mutation, structured gate evidence, and auditability across all tested paths.

## What this experiment does not demonstrate

It does not show that an autonomous model can perform high-quality literature review, design a valid protocol, execute arbitrary real experiments, or write a scientifically correct report. The included executor intentionally supplies deterministic synthetic artifacts/evidence. Real adapters and independent verification remain required.
