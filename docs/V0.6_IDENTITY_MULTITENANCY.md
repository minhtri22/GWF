# v0.6 Identity / Multi-tenancy

v0.6 moves GWR from a single-organization production foundation to a tenant-aware runtime boundary.

The implementation deliberately preserves the v0.5.1 project-centric kernels. Instead of adding tenant columns to every historical table and breaking the proven storage contract, `project_scopes` binds each new project to one workspace and tenant. Every existing authoritative row already carries `project_id` directly or is reachable through it. Public access is therefore gated by `TenantService.require_project_access()` before entering the domain kernels.

Important security rule: **tenant-scoped projects do not trust `actors.project_scope` as authorization**. That field remains for backward compatibility with legacy/unscoped projects and internal domain policies. Tenant membership is authoritative for scoped projects.

OIDC support is verifier-injected. The runtime does not parse an unsigned JWT or trust arbitrary claims. A deployment adapter must cryptographically verify the provider token and return verified claims. GWR then checks issuer/subject and resolves the pre-bound external identity. An `actor_id` claim in the token is ignored.

v0.6 is still not the distributed-runtime milestone. Queueing, worker leases, distributed idempotent execution and chaos recovery remain v0.7 scope.
