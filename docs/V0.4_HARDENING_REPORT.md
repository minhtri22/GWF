## Authenticated approval and recovery
The v0.4 runner creates a HUMAN actor with a credential but does not pass a human actor-id shortcut into the orchestrator.

For every normative change:
1. execution pauses;
2. the human authenticates;
3. a signed, revocable session is issued;
4. the exact frozen proposal hash is approved;
5. the approval session is revoked;
6. execution resumes from checkpoint.

The pilot intentionally exercises semantic recovery. Its first experiment plan has too few pilot grid points relative to the precommitted protocol. The runtime records `pilot_degenerate`, identifies `experiment_plan` as the root, creates a `CONFIRM_ROOT` proposal, pauses, obtains authenticated human confirmation, computes ImpactSet/RecoveryPlan, invalidates the affected subgraph, increments lineage generation and resumes at phase 06. The repaired pilot and all downstream phases then pass.
