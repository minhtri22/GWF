# v0.5.1 — Live PostgreSQL Gate

## Objective

Close the live PostgreSQL gate before starting v0.6 Identity / Multi-tenancy. The gate is intentionally binary: it only passes after the same regression suite and six research cases run on a real PostgreSQL database, a runtime restart is exercised mid-workflow, and SQLite/PostgreSQL semantic snapshots are equal.

## Implemented gate harness

- `tools/run_v051_gate.py` — executes the entire gate.
- `tools/run_v051_restart_probe.py` — closes/reopens the runtime connection mid research workflow and byte-compares stable state/evidence/checkpoint snapshots.
- `tools/compare_v051_semantics.py` — compares backend-independent semantic snapshots from all six benchmark cases.
- PostgreSQL namespace isolation via `GWR_TEST_NAMESPACE_PREFIX`.

## Current run result

**BLOCKED_ENVIRONMENT — not PASS. v0.6 remains blocked.**

The available execution environment has no PostgreSQL server, no psycopg driver, no user-supplied PostgreSQL DSN, and outbound package installation is unavailable. The project therefore does **not** claim live PostgreSQL validation.

What was verified in this environment:

- SQLite regression suite: **41/41 PASS**.
- SQLite research benchmark: **6/6 cases match expected PASS / scientific FAIL / PIVOT semantics**.
- Kernel implementation QA: **PASS**.
- v0.5 production-foundation QA: **PASS**, with PostgreSQL explicitly reported as `READY_NOT_LIVE_TESTED`.

## Exact command to close the gate

```bash
export GWR_TEST_DATABASE_URL='postgresql://USER:PASSWORD@HOST:5432/DBNAME?sslmode=require'
export PYTHONPATH=src
python tools/run_v051_gate.py --out evidence/v0.5.1/live_postgres_gate
```

The PostgreSQL role must be able to create/drop schemas used for isolated test namespaces. Use a disposable database.

## PASS criteria

```json
{
  "status": "PASS",
  "postgres_live_tested": true,
  "same_41_tests_sqlite_and_postgres": true,
  "six_research_cases_sqlite_and_postgres": true,

```

Until that file is produced from a real PostgreSQL run, v0.6 must not start.
